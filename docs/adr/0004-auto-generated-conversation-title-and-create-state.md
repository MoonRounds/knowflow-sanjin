# ADR 0004：AI 自动生成会话标题 + 「➕ 空白态 / 已开始才新建」会话创建语义

- 状态：已接受
- 日期：2026-08-12
- 决策人：项目 Owner
- 关联：ADR 0003、DECISIONS §8、Phase 09 PLAN §3.1

## 背景

现有会话创建体验要求用户在新建会话时手动输入标题：前端 `ChatView.vue` 使用
`ElMessageBox.prompt` 强制填写标题（空标题拒绝），后端 `CreateConversationRequest.title`
为 `@NotBlank` 必填。该流程步骤繁琐，且「每次点击 ➕ 都会创建一条空会话记录」，存在
连点 ➕ 导致空会话堆积的问题。

DECISIONS §8 原决策为「标题默认取首条 User Message 安全截断，可手动改名，不调用 AI 生成标题」，
不满足「AI 自己生成标题」的需求，需要按 §19 变更决策并新增 ADR。

## 决策

### 1. AI 自动生成会话标题

- 标题在**首轮回答结束后**异步生成，不阻塞首轮回答展示。
- 生成来源是**首轮完整对话**（User + Assistant），而非仅首条消息。
- Prompt 要求模型生成一句话标题，中文 10～20 字；存储层按字段长度兜底截断。
- 生成失败或超时**静默回退**为首条 User Message 安全截断标题（与 DECISIONS §8 原规则一致），
  用户无感知；占位标题为「新对话」。
- 取消 DECISIONS §8「不调用 AI 生成标题」的限制，保留「可手动改名」。
- 生成调用必须显式使用 Utility Model（即 `utilityModelConfigId`），避免占用对话 ChatModel。

### 2. 「➕ 空白态 / 已开始才新建」会话创建语义

- 「限流」的语义是**状态机**而非时间窗口：点击 ➕ 的行为取决于当前会话是否「已开始」。
- 「已开始」= 会话内已存在至少一条用户消息（含 AI 仍在 streaming 回答时）。
- 尚未开始时点击 ➕ **不新建会话**，停留在同一个空白会话；已开始时点击 ➕ 才创建新会话。
- 侧栏顶部展示唯一「新对话」占位项（选中态），同一时刻最多一个；空白区发首条消息后才真正落库，
  占位项随之变为真实会话。该占位项天然幂等，任意时刻最多一个空白会话。
- **不引入后端时间窗口频率限流，也不引入前端 debounce**：状态机语义已防连点堆叠，
  时间窗口会误伤「用户同时开两个不同问题会话」的合理操作，且引入倒计时等待，体验更差。

### 3. 数据模型影响

- `conversation` 表无需新增字段：标题仍存于 `title`；「首条 User Message 截断标题」仍作为
  生成前的落库标题与失败回退。
- 需要新增一个**后端异步生成标题任务**，在首轮回答完成后触发；任务在 MySQL 有事实记录，
  可重试，失败静默回退。
- 前端不再弹窗强制填标题；`CreateConversationRequest.title` 由必填改为可选（或前端发送时
  可省略 title，由后端生成/截断兜底）。

## 影响

- 会话创建体验从「填标题 + 立即建空会话」变为「点 ➕ 进入空白态 → 发首条消息才落库 → AI 自动起标题」。
- 空会话堆积问题被消除：任意时刻最多一个「新对话」占位项。
- 连点 ➕ 不再产生多个会话；状态机语义取代时间窗口限流。
- 标题生成是异步、可重试、失败静默回退的 Utility Model 调用，不进入 Chat 主链路。
- 后端需同步调整：`title` 可选 + 首条消息截断兜底 + 首轮后触发标题生成任务。

## 决策变更

- DECISIONS §8 标题决策更新为：AI 自动生成标题 + 首条消息截断兜底 + 可手动改名。
- Phase 09 PLAN §3.1 正式前端产品闭环补充该交互语义与限流语义。
