## 3. 数据与 API 语义

### 3.1 `RetrievedSource`（SSE `sources.available` + `MessageResponse.sources` 共用）

- 新增字段：`knowledgeBaseId`（String，BIGINT 字符串化）、`knowledgeBaseName`（String）。
- 组装点：`RetrievalService.validateAndLoad` 中 `enabledKbById.get(document.getKbId())` 已在手边，直接写入。
- 老 `generation_trace.sources_json` 反序列化后新字段为 null，前端按 G33 隐藏 KB 名行；不迁移存量 trace。

### 3.2 文档列表 VO（`KnowledgeDocumentSummaryResponse`）

- 新增字段：`parseStatus`、`parseErrorCode`、`parseErrorMessage`（String 可空，来自 `file_metadata`；非上传文档为 null）、`indexErrorCode`、`indexErrorMessage`（String 可空，document 列直出）。
- 查询：分页主查询后按 documentIds 批量查 `file_metadata` 聚合（`documentId ∈ ids`），避免逐条 N+1。
- 不做解析状态的「单字段聚合」，前端负责映射展示（G34）。

## 8. 验收标准（承接 v1.5 计划）

- 引用面板显示「所属知识库 + 来源类型」；KB 名缺失的老消息不显示占位符
- 正文 `[S1]` 可悬停预览 snippet、可点击展开并高亮来源面板对应项；集合外编号纯文本
- 文档列表两段状态聚合展示正确（解析中/索引中/已索引/失败 + 错误码 tooltip）
- `verify-all.sh` 全绿；三闭环 E2E 通过
- DECISIONS / ADR 0009 / README 与实现一致；无 `knowledge-items` 残留引用
