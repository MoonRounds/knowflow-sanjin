## 1. In Scope

- V13 为 `conversation` 增加可空 JSON `knowledge_base_ids`。
- Conversation 创建、查询、列表、更新契约增加 `knowledgeBaseIds`。
- 新绑定只接受当前 Owner 下存在、未删除、启用的知识库；允许尚无可检索文档的空库。
- 发送和重新生成在 Tx1 行锁内冻结会话绑定；之后的修改只影响下一轮。
- Router 支持 `AUTO` / `MANUAL`：手动模式只在绑定集合内判断是否需要 RAG 和选择 0～3 个库。
- Chat 空白态可预选库，首条消息创建会话时持久化；既有会话可在顶部面板修改绑定。
- OpenAPI、生成类型、迁移/后端/前端/E2E 测试同步。

## 2. Out of Scope

- Phase 4 的引用悬停/点击增强、来源面板增强、文档处理状态聚合。
- 每库均衡检索、混合检索、语义搜索、Tag 参与 RAG。
- 让 Conversation 绑定影响 Extraction/Candidate。
- 独立 Review、push、PR 或任何 Phase 4 实施。

## 3. 数据与 API 语义

- 数据库 `NULL` 表示 AUTO；创建未传或传 `[]` 均写 `NULL`。
- API 始终返回数组，AUTO 返回 `[]`。
- PATCH 字段缺失表示不修改，显式 `[]` 表示清空并回到 AUTO；`null` 非法。
- 最多绑定 50 个库；服务端去重后按数字 ID 升序保存和响应，顺序不表达优先级。
- 仅当 PATCH 包含 `knowledgeBaseIds` 时强制 `rowVersion`，用版本条件原子更新，冲突返回 409。
- 历史/失效绑定保留在会话 JSON 中；不会阻止知识库禁用/删除，也不会自动改为 AUTO。

## 4. Router、检索与 Trace

- AUTO 完全保持现有目录与 `catalog-limit` 行为。
- MANUAL 使用本轮冻结绑定中仍存在、启用且至少有一个可检索文档的全部库，不应用 AUTO catalog limit。
- 手动绑定全部失效时保持 MANUAL 并返回 `NOT_AVAILABLE`；禁止回退 AUTO。
- 问题无关由 Router 返回 `NOT_NEEDED`；检索继续使用 OR filter + 全局 Top-K。
- `RouterTrace.mode` 每轮记录；实际进入检索时 `RetrievalTrace.mode` 记录相同模式，未检索时保持 `retrieval_json = null`。

## 5. 前端状态机

- 沿用 ADR 0004 懒创建；空白态选库只存本地草稿，首条发送时随创建请求提交。
- 收起态显示“自动选择”或“已绑定 N 个库”；弹层内多选并显式保存。
- 保存成功后刷新本地 Conversation；失败保留服务器旧值。
- 生成连接/流式期间禁止编辑，并提示修改从下一轮生效。
- 禁用绑定显示“已停用”，已删除绑定显示“不可用知识库 #ID”；不静默清除。
- 知识库列表加载失败时禁止保存，不能以 `[]` 覆盖现有绑定。

## 8. 验收标准

- 手动绑定 1 个或多个库时，Router 与检索不越出绑定范围。
- 手动模式问题无关时普通回答；绑定全部失效时 `NOT_AVAILABLE`，不回退 AUTO。
- 0 库的新旧会话继续使用原 AUTO 行为。
- 会话内修改只从下一轮生效，发送与重新生成均使用 Tx1 快照。
- 前端空白态、会话切换、清空 AUTO、失败回滚、失效绑定和生成中限制可验证。
- Extraction/Candidate 回归不受影响；Phase 4 功能未提前实现。
