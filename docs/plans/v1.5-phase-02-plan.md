## 1. In Scope（承接 v1.5 计划 Phase 2）

- 路由：`/knowledge-bases`（库列表）、`/knowledge-bases/:id`（库详情 = 该库文档列表 + 过滤 + 新建笔记/上传入口）、`/documents/:id`（文档详情）
- 后端：`GET /documents` 分页 + 过滤；`GET /tags`；`KnowledgeBaseResponse.documentCount`
- 前端：`KnowledgeBasesView` 拆分为库列表页；新增 `KnowledgeBaseDetailView`；`KnowledgeItemDetailView → KnowledgeDocumentDetailView`；上传/新建笔记对话框迁入库详情页；Tag 过滤 UI；旧路由 `/knowledge-items/:id` → redirect `/documents/:id`
- 回归：聊天、候选、处理页跳转；`FlowView` 最近活跃

## 2. Out of Scope（明确排除，评审不得当作缺陷）

- 手动选库问答（P3）、`conversation.knowledge_base_ids`
- 状态聚合展示增强与引用增强（P4：失败错误码聚合展示、来源面板补 KB 名、正文 `[S1]` 交互）
- 跨库「全部文档」视图（文档只能从某库进入）
- 语义搜索、每库均衡检索、Tag 参与 RAG（V2.0）
- 库详情页的库编辑/禁用/删除（CRUD 留在库列表页）

## 3. API 契约变更

1. `GET /documents`（G22）：
   - query 参数：`knowledgeBaseId`（可选）、`sourceType`（可选）、`tag`（可选，精确匹配 normalized name）、`indexStatus`（可选）、`page`（默认 1）、`size`（默认 20）
   - 响应：`DocumentPageResponse{ items: KnowledgeDocumentSummaryResponse[], page, size, total }`
   - `KnowledgeDocumentSummaryResponse`：`id` / `sourceType` / `title` / `contentVersion` / `indexedVersion` / `indexStatus` / `knowledgeBaseId` / `tags` / `rowVersion` / `createdAt` / `updatedAt`（**无 `content`、无 `summary`、无 indexError 字段**——错误码聚合展示属 P4）
2. `GET /tags`（G23）：返回 owner 全部未删标签 `TagResponse{ id, name }`，按名称排序
3. `KnowledgeBaseResponse` 增加 `documentCount`（G24）：列表接口一次 `GROUP BY kb_id` 统计

`GET /documents/{id}`、`POST/PUT/DELETE /documents`、`GET /knowledge-bases` CRUD、上传 `POST /files` 均不变。

  - `KnowledgeDocumentService`：新增 `pageForOwner(...)`（LambdaQueryWrapper：ownerId + deleted=0 + 可选 eq(kbId/sourceType/indexStatus)；Tag 过滤用两步：先按 `tag.normalized_name` 查 `tag_id`，再查 `knowledge_document_tag`（`deleted=0`）得 documentId 集合，主查询 `.in(id, ...)`；`created_at DESC` 排序；MyBatis-Plus `Page` 分页）。新增 `listTagsForOwner()`（TagMapper selectList ownerId + deleted=0 order by name）

## 8. 验收标准（承接 v1.5 计划）

- 库列表 → 库详情（文档列表）→ 文档详情三页面真实闭环
- 笔记（`MANUAL_NOTE`）作为 `source_type` 过滤视图，无独立「我的笔记」区块
- Tag 过滤生效；上传/新建笔记入口在库详情页正常工作且归属当前库
- 旧链接 `/knowledge-items/:id` 重定向到 `/documents/:id`
- 前端 typecheck/build/单测绿；后端编译/单测/集成测试绿；OpenAPI 契约与 generated.ts 无漂移
- 聊天/候选/处理页跳转回归通过

## 9. 剩余风险

- Phase 1 未独立 Review（G16），重构基于「Phase 1 已可用」假设
- E2E `note-loop.spec.ts` 仅静态同步，未实际运行（需完整栈 + embedding），若 Phase 4 前不跑，需在 Phase 4 E2E 验收时覆盖

- `tag` 过滤两步查询：Tag 不存在时返回空集合（无文档），行为正确但需 IT 覆盖
